# План тестирования Bucard Web Automation

Документ описывает стратегию автоматизированного тестирования веб-приложения Bucard (`https://bucard.az`), структуру тестовых наборов, границы безопасности и критерии приёмки.

---

## 1. Исследованные модули и границы проверок

| Модуль | Назначение / Наблюдаемое поведение | Границы и ограничения |
|---|---|---|
| **Публичный вход / Маршруты** | Главная страница и `/login`; SPA контейнер `#root`. При активной сессии `/login` перенаправляет в кабинет. | Проверка доступности, кода ответа, заголовка документа и чистого рендеринга без 5xx ошибок. |
| **Dashboard (All Boxes / My Box)** | Обзор папок контактов (Boxes), ссылка на профиль, QR/Share, системные уведомления. | Read-only проверка отображения боксов и навигационных ссылок. Не переходить по ссылкам подтверждения email. |
| **Profile** | Цифровая визитка пользователя: Contact info, Portfolio, Experience, Skills, Languages, Keywords, статус Private/Public. | Проверка наличия ключевых секций. Категорически запрещено переключать статус приватности или редактировать данные. |
| **Search** | Поиск профилей («Search personal or business profiles»), поле ввода и результаты. | Проверка доступности формы поиска. Запросы отправлять только по синтетическим фикстурам без поиска реальных лиц. |
| **Box Details** | Детали выбранного бокса, поиск по контактам, кнопка добавления, пустое состояние («User not found» / «No contacts»). | Проверка пустого состояния и полей поиска. Запрещено создавать/удалять контакты на production-окружении. |
| **Settings** | Разделы: Account Center, Plan, Payments, Terms & Privacy, Card Center, Help. | Проверка отображения навигации по разделам. Запрещены любые изменения тарифов, заказ NFC-карт и удаление аккаунта. |

## 2. Уровни приоритетов (Test Priorities)

### P0 — Публичный Smoke (Public Unauthenticated Checks)

- **Цель**: Быстрая проверка жизнеспособности сервиса без необходимости в учётных данных.
- **Реализация**:
  - `SiteAvailabilityTest.siteIsReachable`: проверка загрузки базового URL, наличия слова «Bucard» в title и присутствия контейнера `#root`.
  - `PublicRoutesSmokeTest.loginRouteIsAccessible`: проверка корректной загрузки маршрута `/login` без падения сервера.
  - `PublicRoutesSmokeTest.loginPageHasNoServerError`: проверка отсутствия ошибок 502/500 в DOM страницы.
- **Исполнение**: Запускается в CI на каждый push и pull request, а также по расписанию.

### P1 — Авторизованный Read-Only Smoke (Authenticated Navigation)

- **Цель**: Проверка доступности ключевых внутренних разделов кабинета после авторизации.
- **Условие запуска**: Наличие переменных `BUCARD_TEST_USER` и `BUCARD_TEST_PASSWORD`. Если переменные не заданы, тесты **автоматически пропускаются (`SKIPPED`)**.
- **Реализация**:
  - `AuthenticatedNavigationSmokeTest.dashboardIsAccessibleWhenAuthenticated`: вход и проверка дашборда.
  - `AuthenticatedNavigationSmokeTest.settingsAreAccessibleWhenAuthenticated`: переход в Settings и проверка разделов.
  - `AuthenticatedNavigationSmokeTest.profileIsAccessibleWhenAuthenticated`: переход в Profile и проверка секций.
- **Безопасность**: Учётные данные передаются через защищённые секреты CI / переменные окружения и никогда не выводятся в логи.

### P2 — Регрессионные и Sandbox CRUD сценарии (Будущий этап)

- **Условие**: Выделение отдельного изолированного тестового тенанта (sandbox) с автоматическим сбросом данных.
- **Сценарии**:
  - Создание пользовательского Box, добавление синтетического контакта, удаление созданного тестового бокса.
  - Поиск синтетических тестовых профилей.
  - Проверка валидации полей ввода при некорректных форматах email/телефона.

## 3. Категорически запрещённые действия (Explicit Exclusions)

В рамках автоматизации **запрещено**:
1. Проведение любых платежей, выбор платных планов, смена подписки или автопродления.
2. Заказ физических NFC-карт.
3. Изменение статуса видимости профиля на «Public».
4. Удаление или деактивация аккаунта.
5. Реальная отправка приглашений, сообщений или шеринг персональных данных.
6. Подтверждение email через внешние ссылки.
7. Обход CAPTCHA, SMS/MFA-кодов.

## 4. Сбор артефактов и отчётность

1. **Скриншоты сбоев**:
   - При падении любого теста создаётся скриншот в каталоге `target/screenshots/`.
   - Имена файлов содержат название метода и метку времени, без секретов.
   - В GitHub Actions каталог артефактов сохраняется через `actions/upload-artifact@v4`.
2. **Telegram-уведомления**:
   - Отправка сводного сообщения по окончании прогона (общее число тестов, passed, failed, skipped, длительность, краткая очищенная причина ошибки).
   - Если переменные `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID` не заданы, отправка пропускается без сбоев.
